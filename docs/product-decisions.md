# U-topia product decisions

ข้อสรุปจากการสัมภาษณ์สำหรับรุ่นงานแข่ง ใช้ร่วมกับ `docs/adr/` และ `GLOSSARY.md`; เอกสารนี้ไม่ใช่ implementation spec

## Language

- ภาษาอังกฤษเป็นภาษาหลักของหน้าเว็บและข้อความระบบ
- เนื้อหาผลงานที่ผู้ขายกรอกใช้ภาษาใดก็ได้

## Frontend implementation

- ผู้ใช้เลือก React + JavaScript สำหรับ frontend โดยใช้ Vite เป็น build/dev tooling
- แยก source เป็น pages, components, lib, utils, data, hooks และ styles
- ใช้ `FASTWORK_SELLING_UX_UI_SPEC_TH.md` เป็นแนวทาง UX/UI ของ creator landing โดยปรับตามภาษาอังกฤษและกติกา U-topia ที่ตกลงแล้ว

## Refunds and delivery retries

- รุ่นงานแข่งยังไม่มีระบบคืนเงินอัตโนมัติ
- เมื่อซื้อสำเร็จแต่การรับไฟล์ล้มเหลว ผู้ซื้อที่ยังมีสิทธิ์ต้องลองดาวน์โหลดใหม่ได้โดยไม่ซื้อซ้ำ
- นโยบายนี้เป็นขอบเขตรุ่นงานแข่ง ไม่ใช่ข้อสรุปนโยบายคืนเงินสำหรับการเปิดขายเงินจริง

## Agreed product scope

- กำหนดส่งรุ่นงานแข่ง: 16 ตุลาคม 2026 เวลา 12:00 น. Asia/Bangkok
- เป้าหมายยังครอบคลุมการแสดงผลงาน ทดลอง ซื้อสิทธิ์ รับ source รวมฟีเจอร์ด้วย U-Bot และนำผลงานใหม่กลับมาลงขายตามสิทธิ์ต้นทาง โดยยังไม่รับประกันว่าจะพัฒนาได้ครบตามกำหนด
- พัฒนาครบ frontend, backend และ smart contract ใช้ Avalanche Fuji และ test AVAX สำหรับซื้อขาย
- ใช้ wallet เป็นหลักในการเข้าสู่ระบบ บัญชีเดียวเป็นผู้ซื้อและผู้สร้างได้ พร้อมโปรไฟล์ชื่อ รูป และประวัติ
- ผู้สร้างอัปโหลด source เป็น ZIP; เข้ารหัสก่อนเก็บบน IPFS ปกติ Backend ดูแลกุญแจนอกเชนและตรวจสิทธิ์ก่อนอนุญาตถอดรหัส
- Demo ใช้ URL ที่ผู้สร้าง deploy ไว้แล้ว ผู้ขายเผยแพร่รายการได้โดยไม่รอแอดมินอนุมัติ
- รายการหนึ่งขายให้ผู้ซื้อหลายคนได้ แต่ละคนมี token สิทธิ์ของตัวเอง และได้รับอัปเดตฟรีจากรายการเดิม
- ผู้ซื้อรับ ZIP ไปใช้เอง แพลตฟอร์มไม่ต้องติดตั้งหรือ deploy ให้
- ผู้สร้างกำหนดการขายสิทธิ์เดิมต่อแยกจากการขายผลงานต่อยอด เมื่ออนุญาตให้ต่อยอดเพื่อขาย ผลงานใหม่ขายพร้อม source ได้ ไม่มีส่วนแบ่งรายได้กลับไปยังต้นทาง
- ค่าธรรมเนียม 10% ของราคาขาย ผู้ขายรับ 90% แพลตฟอร์มออก gas ของการซื้อจากส่วน 10% ต้องมีระบบออก gas แทนผู้ซื้อ
- U-Bot ใช้เฉพาะงานรวมหลายโปรเจกต์ ผู้ใช้เลือกฟีเจอร์จากแต่ละโปรเจกต์ได้ ไม่กำหนดเพดานจำนวนโปรเจกต์ตายตัว และเลือก stack เป้าหมายได้
- U-Bot เสนอรายการฟีเจอร์ให้เลือกและพิมพ์เพิ่ม แสดงแผนและโควตาที่คาดว่าจะใช้ก่อนยืนยันสร้างโค้ด ผลลัพธ์ส่งเป็นโค้ด ZIP
- ถ้าโควตาไม่พอ ให้ผู้ใช้เพิ่ม ลด หรือเปลี่ยนฟีเจอร์และประเมินใหม่ โดยยังเริ่มสร้างโค้ดไม่ได้จนกว่าโควตาจะพอ
- โควตา U-Bot เป็นก้อนต่อบัญชีสำหรับช่วงทดลอง ไม่มีรีเซ็ตรายวัน ไม่มีเติมเครดิต และไม่แจกเครดิตอัตโนมัติจากการซื้อ

## AI provider — confirmed 15 October 2026

- ผู้ใช้เลือก Google Gemini API สำหรับ AI Agent ของ U-Bot แทนการพักเลือกผู้ให้บริการในข้อสรุปเดิม รวมถึงข้อความเดิมใน ADR-0006
- Python Backend เรียกผ่าน Google Gen AI SDK (`google-genai`) และเก็บ `GEMINI_API_KEY` เป็น server-side environment variable บน Railway ไม่ส่ง key ไป frontend
- ใช้ Gemini วิเคราะห์ source เสนอฟีเจอร์/แผน และสร้างโค้ดหลังผู้ใช้ยืนยัน แยกจาก sandbox สำหรับรัน build/test
- รุ่นโมเดลให้กำหนดผ่าน `GEMINI_MODEL`; ยังไม่ได้เลือกรุ่น โควตา หรือยืนยันว่าเรียก API จริงสำเร็จ

## Pending details

Implementation update 16 October 2026: the user reconfirmed Avalanche Fuji (43113). The Python/backend versus Solidity responsibility split is recorded in `backend-marketplace-handoff.md`. Gemini uses Free Tier for the demo with no automatic paid fallback. Native escrow setup gas and single-relayer limitations are explicit implementation limits; full external acceptance is still pending.

- ต้องเตรียม Gemini API credentials เลือกรุ่นโมเดล และตรวจ rate limits/ราคา/เงื่อนไขการใช้ข้อมูลของ tier ที่จะใช้งาน
- จำนวนโควตาและสูตรคิดต้นทุนต้องอิงโมเดลที่เลือก รวมถึงกติกาคิดโควตาช่วงวิเคราะห์ งานล้มเหลว และวันสิ้นสุดช่วงทดลอง
- วิธีนำเข้า open source และการตรวจเงื่อนไขที่เข้ากันได้ยังต้องออกแบบตาม flow ต้นฉบับของผู้ใช้
- วิธีออก gas แทนผู้ซื้อ มาตรฐาน token การเก็บกุญแจ และวิธีตรวจผลลัพธ์ U-Bot ยังต้องออกแบบทางเทคนิค
- ความสัมพันธ์ของสิทธิ์อัปเดตกับการขายต่อและการเปลี่ยนเงื่อนไขรุ่นใหม่ยังต้องระบุให้ชัด
