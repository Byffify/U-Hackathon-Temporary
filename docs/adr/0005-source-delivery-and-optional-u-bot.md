# ส่งมอบโค้ดและใช้ U-Bot ตามความต้องการหลังซื้อ

U-topia ส่งมอบโปรเจกต์ต้นฉบับให้ผู้ซื้อเป็น ZIP และผู้ซื้อนำไปติดตั้ง รัน หรือ deploy เอง โดยแพลตฟอร์มไม่ต้อง deploy ผลงานให้ ตามข้อสรุปล่าสุด U-Bot ใช้เฉพาะงานรวมโค้ดหลายโปรเจกต์ และส่งมอบโค้ดผลลัพธ์กลับไปใช้ต่อ แทนขอบเขตเดิมที่รวมงานปรับปรุงโปรเจกต์เดี่ยวด้วย

## Consequences

- U-Bot เป็นขั้นตอนเสริมหลังซื้อ ไม่ใช่เงื่อนไขบังคับก่อนรับ source
- Demo ของผลงานใช้ URL ที่ผู้สร้าง deploy ไว้แล้ว
- ระบบตรวจสิทธิ์เข้าถึง source และเงื่อนไขการดัดแปลงหรือขายต่อยอดยังใช้กับการทำงานของ U-Bot
- การส่งมอบโค้ดไม่ได้เพิ่มสิทธิ์นอกเหนือเงื่อนไขที่ผู้ซื้อได้รับ
- โปรเจกต์ที่ขายใช้ภาษาและ framework ตามที่ผู้สร้างเลือก U-Bot ใช้ stack เดิมเป็นค่าเริ่มต้น และไม่บังคับแปลงเป็น React หรือ Next.js
- ลูกค้าเลือก stack เป้าหมายได้ หากต้องเปลี่ยน stack หรือรวมโปรเจกต์ต่าง stack ให้ U-Bot วิเคราะห์และเสนอแนวทาง แล้วรอให้ลูกค้าเลือกหรือยืนยันก่อนดำเนินการ
- การเลือก stack เป้าหมายไม่ใช่การรับประกันว่า U-Bot จะรวมโปรเจกต์ทุกคู่ได้สำเร็จ วิธีตรวจคุณภาพและรายงานข้อจำกัดของผลลัพธ์ยังต้องกำหนดก่อนออกแบบการทำงาน
- ผู้ใช้เลือกต้นทางได้หลายโปรเจกต์โดยไม่กำหนดเพดานจำนวนโปรเจกต์ตายตัว และเลือกเฉพาะฟีเจอร์จากแต่ละโปรเจกต์เพื่อประกอบผลงานใหม่ได้ แทนการบังคับรวมทั้งโปรเจกต์ทุกส่วน
- U-Bot วิเคราะห์ต้นทางและเสนอรายการฟีเจอร์ให้ผู้ใช้เลือก ผู้ใช้พิมพ์ความต้องการเพิ่มได้ และต้องเห็นแผนการรวมก่อนกดยืนยันเริ่มงานสร้างโค้ด
- ขั้นวิเคราะห์และเสนอแผนแยกจากการเริ่มรวมโค้ดที่ผู้ใช้ยืนยัน รายละเอียดการคิดโควตาของแต่ละขั้นยังไม่ได้กำหนด
- จำนวนโปรเจกต์ที่เลือกไม่ได้ยกเลิกโควตาการประมวลผลตาม ADR-0006; งานที่เกินขีดความสามารถจริงต้องมีวิธีแบ่งงานหรือรายงานข้อจำกัด โดยยังไม่ได้กำหนดรายละเอียดการจัดการ
